## 2 Сценарії інтеграційного та End-to-End тестування

### Сценарій E2E-01: Життєвий цикл замовлення клієнта
1. **Реєстрація нового користувача** через `POST /api/v1/auth/register` з валідними даними (email, телефон, пароль).
   * *Результат:* 201 Created, повернення структури користувача з прихованим хешем пароля.
2. **Автентифікація** через `POST /api/v1/auth/login`.
   * *Результат:* 200 OK, повернення JWT Bearer токена.
3. **Запит каталогу меню** `GET /api/v1/menu/items`.
   * *Результат:* 200 OK, отримання списку страв та категорій.
4. **Створення замовлення** `POST /api/v1/orders` з двома позиціями та часом самовивозу.
   * *Результат:* 201 Created, сума розрахована коректно, статус `pending`.
5. **Перевірка списку замовлень клієнта** `GET /api/v1/orders`.
   * *Результат:* 200 OK, створене замовлення присутнє у списку.

### Сценарій E2E-02: Робота бариста та керування статусами
1. **Вхід адміністратора** через `POST /api/v1/auth/login` з обліковими даними суперкористувача.
2. **Отримання загальної черги замовлень** через `GET /api/v1/orders/admin`.
   * *Результат:* 200 OK, перелік замовлень усіх клієнтів із деталізацією.
3. **Почергове оновлення статусу** через `PATCH /api/v1/orders/{id}/status`:
   * `pending` ➔ `preparing` (статус 200 OK);
   * `preparing` ➔ `ready` (статус 200 OK);
   * `ready` ➔ `completed` (статус 200 OK).

### Сценарій E2E-03: Керування стоп-листом та захист RBAC
1. **Звичайна спроба неавторизованого доступу** до `PATCH /api/v1/menu/items/{id}/availability`:
   * *Результат:* 401 Unauthorized (без токена).
2. **Спроба доступу звичайного гостя** без прав суперкористувача:
   * *Результат:* 403 Forbidden (недостатньо прав).
3. **Успішне перемикання доступності адміністратором**:
   * *Результат:* 200 OK, `is_available: false`.
