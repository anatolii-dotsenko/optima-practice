# РЕЄСТР ВИЯВЛЕНИХ ДЕФЕКТІВ (DEFECT LOG)

**Проєкт:** Вебсистема онлайн-замовлень у кав'ярні (Optima Coffee)  
**Версія:** v1.0.0  
**Дата аудиту:** 12.09.2026  

---

## 1 Загальна статистика дефектів

У ході інтеграційного, кросбраузерного та користувацького тестування функціоналу системи (Спринти 1–3) було зафіксовано та успішно усунено наступні дефекти:

| ID | Назва дефекту | Пріоритет | Компонент | Статус |
|---|---|---|---|---|
| BUG-01 | Скидання лічильника кількості на кнопку «+ У кошик» після анімації | Medium | Frontend (Menu Card) | Fixed |
| BUG-02 | Відсутність зображення для позиції «Круасан з мигдалевим кремом» | Low | Frontend (Assets / Seed) | Fixed |
| BUG-03 | Доступність замовлення позицій, переведених у стоп-лист | High | Backend & Frontend | Fixed |

## 2 Детальний опис виявлених дефектів

### BUG-01: Скидання блоку кількості `+/-` на початкову кнопку після анімації додавання

- **Пріоритет:** Medium
- **Середовище:** Google Chrome 128 (Desktop & Mobile), Apple Safari 17.5
- **Опис:** При натисканні на кнопку «+ У кошик» у картці страви відтворювалася анімація «Додано! ✓», після завершення якої стан картки знову повертався до вихідної кнопки «+ У кошик» замість збереження блоку регулювання кількості `- [ 1 ] +`.
- **Кроки для відтворення:**
  1. Відкрити сторінку каталогу меню `http://localhost:3000/`.
  2. Знайти будь-яку доступну страву (наприклад, «Капучино»).
  3. Натиснути кнопку «+ У кошик».
  4. Зачекати завершення анімації (800 мс).
- **Очікуваний результат:** Кнопка замінюється на контролер кількості з кнопками декременту `-`, відображенням поточної кількості та інкременту `+`.
- **Фактичний результат:** Кнопка поверталася до початкового стану «+ У кошик», що змушувало користувача клікати повторно.
- **Виправлення:** У компоненті `renderMenuGrid` додано перевірку наявності товару в кошику (`cart.getItemQuantity(item.id)`) та динамічний рендеринг кнопок регулювання кількості без скидання після анімації.

### BUG-02: Відсутність URL-зображення для десерту «Круасан з мигдалевим кремом»

- **Пріоритет:** Low
- **Середовище:** Всі підтримувані браузери
- **Опис:** У каталозі меню картка круасана з мигдалевим кремом відображала плейсхолдер ☕ замість якісного фотографічного зображення випічки через відсутність валідного посилання на зображення у початкових даних.
- **Кроки для відтворення:**
  1. Перейти до вкладки «Десерти» у меню.
  2. Переглянути картку «Круасан з мигдалевим кремом».
- **Очікуваний результат:** Відображення фотографії свіжого круасана.
- **Фактичний результат:** Відображалася сіра заглушка з емодзі ☕.
- **Виправлення:** Оновлено початкову міграцію та сид-дані бази даних: додано валідне посилання на фотографію Unsplash з високою роздільною здатністю та оптимізованим форматом.

### BUG-03: Можливість оформлення замовлення на позиції зі стоп-листа при прямій відправці запиту

- **Пріоритет:** High
- **Середовище:** Backend API (`POST /api/v1/orders`)
- **Опис:** Якщо позиція меню була додана користувачем у кошик до переведення її адміністратором у стоп-лист (`is_available = False`), прямий запит на створення замовлення завершувався успішно без валідації актуальної доступності на рівні бази даних.
- **Кроки для відтворення:**
  1. Користувач додає «Фільтр-каву» у кошик.
  2. Адміністратор вимикає доступність «Фільтр-кави» в адмін-панелі.
  3. Користувач надсилає запит на створення замовлення.
- **Очікуваний результат:** Сервер відхиляє замовлення з HTTP-кодом 400 Bad Request та повідомленням «Позиція більше не доступна для замовлення».
- **Фактичний результат:** Замовлення успішно створювалося зі статусом 201 Created.
- **Виправлення:** У сервісному шарі `OrderService.create_order` додано сувору перевірку прапорця `is_available` для кожного елемента замовлення перед відкриттям транзакції збереження.
